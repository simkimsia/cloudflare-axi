# Contributing

Thanks for wanting to contribute.
One rule up front:

**Pull requests targeting `main` should be raised through [`no-mistakes`](https://github.com/kunchenguid/no-mistakes).**
It keeps review effort low for a one-person project.

`no-mistakes` puts a local git proxy in front of your real remote.
Pushing through it runs an AI-driven review, test and lint pipeline in an isolated worktree, forwards the push upstream only after every check passes, and opens a clean PR automatically.

## Workflow

1. Fork the repo, then clone the parent repo or set your local `origin` back to the parent repo (`git@github.com:simkimsia/cloudflare-axi.git`).
2. Create a branch and make your changes.
3. Initialize or refresh the gate with your fork as the push target: `no-mistakes init --fork-url git@github.com:<you>/cloudflare-axi.git`.
4. Commit your changes with a [conventional commit](https://www.conventionalcommits.org/) message (`feat:`, `fix:`, `docs:`, `ci:` and so on).
5. Push through the gate instead of pushing to `origin`:

   ```sh
   git push no-mistakes
   ```

6. Run `no-mistakes` to attach to the pipeline, watch findings, and fix or review as needed.
7. Once the pipeline passes, it pushes the branch to your fork and opens the PR against this repo for you.

See the [no-mistakes quick start](https://kunchenguid.github.io/no-mistakes/start-here/quick-start/) for the full first-run walkthrough.

## Repo conventions

- Node 20+, TypeScript, ESM-only.
- Install dependencies with `pnpm install --frozen-lockfile`; run `pnpm run build`, `pnpm run format:check` and `pnpm test` before pushing. CI runs the same steps on Node 24.
- Do not hand-edit `CHANGELOG.md` or `.release-please-manifest.json`.
  They are regenerated by release-please from your conventional commit messages.
- Do not bump `package.json`'s `version` by hand for ordinary changes.
  release-please updates it in the release PR.
- Keep install steps in `README.md` only.
  The Setup section of `skills/cloudflare-axi/SKILL.md` points to the README, because the skill ships inside the npm package and a copied install block goes stale in every published version.

## Releases

release-please cuts releases from conventional commits on `main`.
Merging its release PR publishes `@simkimsia/cloudflare-axi` to npm through `.github/workflows/release-please.yml`, using npm trusted publishing, so no npm token is stored in the repo.

`ci.yml` and `guard-generated-files.yml` both `paths-ignore` the release-please output set (`.release-please-manifest.json`, `CHANGELOG.md`, `package.json`) so a release PR creates no runs.
release-please opens that PR with `GITHUB_TOKEN`, and a run created that way would sit in `action_required` and never start.
Update the ignore lists if `release-please-config.json` gains `extra-files` or changes `release-type`.
